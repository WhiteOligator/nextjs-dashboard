# Acme Dashboard

full-stack приложение — финансовая панель управления. Проект показывает, как собрать современное приложение на Next.js App Router: с базой данных, аутентификацией, серверными действиями (Server Actions), потоковой отрисовкой и деплоем на Vercel.

---

## Зачем этот проект

Цель — на практике разобрать ключевые возможности Next.js на примере реального интерфейса: дашборд с метриками выручки, список счетов с поиском и пагинацией, управление клиентами и защищённый вход. Это не продакшн-продукт, а обучающий, но написан по продакшн-паттернам.

## Возможности

- **Дашборд** с карточками метрик, графиком выручки и списком последних счетов.
- **Счета (Invoices):** создание, редактирование, удаление, поиск по мере ввода и пагинация.
- **Клиенты (Customers):** список клиентов.
- **Аутентификация** по логину/паролю через NextAuth.js (Credentials), с защитой маршрутов дашборда.
- **Серверные действия (Server Actions)** для мутаций данных без отдельного API-слоя.
- **Валидация форм** через Zod и обработка ошибок.
- **Потоковая отрисовка (Streaming)** через `loading.tsx` и `<Suspense>` — контент подгружается частями.
- **SEO-метаданные** на всех маршрутах, включая динамический заголовок на странице редактирования счёта.
- **Адаптивная вёрстка** на Tailwind CSS.
- **Кастомные страницы** ошибок (`error.tsx`) и «не найдено» (`not-found.tsx`).

## Переменные окружения

Создай файл `.env` в корне (проще всего скачать готовый набор из Vercel):

```bash
vercel env pull .env
```

Ключевые переменные:

| Переменная | Назначение |
|---|---|
| `POSTGRES_URL` | строка подключения к PostgreSQL (используется в приложении) |
| `AUTH_SECRET` | секрет для NextAuth (сгенерировать: `openssl rand -base64 32`) |

> Файл `.env` содержит секреты и **не коммитится** в git (он в `.gitignore`).

## Запуск локально

```bash
# 1. Установить зависимости
pnpm install

# 2. Забрать переменные окружения из Vercel (или создать .env вручную)
vercel env pull .env

# 3. Заполнить базу тестовыми данными (один раз)
pnpm run dev
# затем открыть в браузере http://localhost:3000/seed

# 4. Запустить дев-сервер
pnpm run dev
```

Приложение будет доступно на **http://localhost:3000**.

> После первого сида файлы `app/seed/route.ts` и `app/query/route.ts` можно удалить — они нужны только для инициализации/проверки БД.

## Деплой на Vercel

1. Залей проект в репозиторий на GitHub.
2. На [vercel.com](https://vercel.com) → **Add New → Project** → импортируй репозиторий.
3. В разделе **Storage** создай/подключи базу **Postgres (Neon)** к проекту — переменные `POSTGRES_*` добавятся автоматически.
4. Добавь переменную `AUTH_SECRET` в **Settings → Environment Variables**.
5. Нажми **Deploy**.
6. После первого деплоя открой один раз `https://<твой-домен>.vercel.app/seed`, чтобы заполнить продакшн-базу (потом удали seed-роут).

Каждый `git push` в основную ветку будет автоматически пересобирать и деплоить приложение.

```
├── page.tsx                # главная (лендинг)
├── login/                  # страница входа
├── dashboard/
│   ├── layout.tsx          # layout дашборда (боковое меню)
│   ├── (overview)/         # главная дашборда + loading.tsx (streaming)
│   ├── customers/          # список клиентов
│   └── invoices/           # счета: список, создание, редактирование, error/not-found
├── lib/
│   ├── actions.ts          # Server Actions (создание/редактирование/удаление, вход)
│   ├── data.ts             # запросы к БД
│   ├── definitions.ts      # типы TypeScript
│   └── utils.ts            # утилиты (форматирование и пр.)
└── ui/                     # переиспользуемые компоненты и стили
auth.ts, auth.config.ts     # конфигурация NextAuth
```

## Идеи для развития

- **Регистрация пользователей** и роли/права доступа.
- **CRUD для клиентов** (сейчас только список) — добавление, редактирование, удаление.
- **Тёмная тема** и переключатель.
- **Тесты**: unit (Vitest/Jest) на утилиты и Server Actions, e2e (Playwright) на ключевые сценарии.
- **CI/CD**: GitHub Actions с прогоном линта, типов и тестов перед деплоем.
- **Экспорт счетов** в PDF/CSV.
- **Дополнительные метаданные**: Open Graph и Twitter-карточки для красивых превью ссылок.
- **Мониторинг**: Vercel Analytics и Speed Insights.
- **OAuth-провайдеры** (Google/GitHub) в дополнение к входу по паролю.
